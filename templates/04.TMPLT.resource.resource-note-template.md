# Template: Resource Note

> Use this for reference material — anything you'll want to look up later but that doesn't have a "done" state and doesn't need to be maintained on a schedule. A resource note is the answer to "what did I decide/learn/collect about X?", not "what do I need to do about X?"

## What this template is for

A resource note captures reference material: a guide, a checklist, a decision you want to remember the reasoning for, a curated list of links, a cheat sheet. If a note would need a `Status` field or a `Todo` section, it's probably a Project or Area instead — resource notes are read, not worked.

## Required frontmatter fields

```yaml
---
Type: "Resource"
---
```

Resource notes intentionally carry the lightest frontmatter of any type — there's no status to track and no priority to weigh, so one field is enough. Add more only if you actually query on them later (a `Topic:` field, for instance, if you tag resources by subject and want to filter).

## Required sections

1. `## <Topic heading>` — the resource's actual content. Unlike Project/Area/Goal notes, a Resource note doesn't force a fixed section list beyond this — organize the body however suits the material (a table, a checklist, a set of sub-headings).
2. `## Notes` — optional: where this came from, when it was last verified accurate, related resources.

## Notes on using this template

- **Don't let a resource note quietly become a project.** If you catch yourself adding checkboxes for things you personally still need to *do*, that content belongs in a Project or Area, not here — link out to it instead of merging it in.
- Resource notes don't expire the way Areas need upkeep or Projects reach "done" — but a stale resource note (a checklist for a tool you no longer use, a guide for a process that changed) is still clutter. Skim the Resources folder occasionally and archive what no longer applies.
- Resource notes are a natural home for anything a template or process references repeatedly — instead of copy-pasting the same checklist into three project notes, put it once in Resources and link to it from each project.
