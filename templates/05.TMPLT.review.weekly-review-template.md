# Template: Weekly Review

> A weekly review is a short, dated check-in note — not a project and not a daily note. It's where you step back once a week and look across everything at once, instead of only ever seeing one project or one day at a time.

## What this template is for

Daily notes capture what happens *today*. Project and Area notes track what's happening *within one thread of work*. A weekly review is the one note type whose whole job is to look sideways across all of it, once a week, and ask "given everything, what actually matters next?" Use it every week on a fixed day (Friday afternoon and Sunday evening both work well — pick one and keep it consistent).

## Required frontmatter fields

```yaml
---
Type: "Weekly Review"
Week: "<e.g. 2026-W04>"
---
```

Weekly reviews are dated like daily notes rather than numbered like Projects/Areas — see the "when to break the pattern" note in the numbering guide.

## Required sections

1. `## Wins this week` — what actually got finished or moved forward; keep this short and specific, not a vague "good week."
2. `## What's stuck` — anything that hasn't moved in a week or more, and why (if you know why).
3. `## Across projects and areas` — a quick scan: for each active Project and Area, one line on its state. This is the section that catches things falling through the cracks between individual project notes.
4. `## Next week's focus` — 1–3 things, not a restated to-do list. If everything is "next week's focus," nothing is.

## Notes on using this template

- **Keep it short.** A weekly review that takes 45 minutes to write stops happening after a month. Ten focused minutes, done every week, beats an hour done occasionally.
- The "Across projects and areas" section is the main defense against a project quietly going stale — if you can't write a one-line update for something, that's itself useful information (it means nothing happened on it all week).
- Weekly reviews live in their own `Weekly_reviews/` folder at the vault root (the same kind of dated-not-numbered exception as `Daily_notes/`), one file per week, named by ISO week number so they sort correctly.
- If a weekly review keeps surfacing the same stuck item three weeks running, that's usually a sign the task itself is unclear or too big — break it down rather than carrying it forward unchanged a fourth time.
