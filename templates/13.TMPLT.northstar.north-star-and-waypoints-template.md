# Template: North Star & Waypoints

> A `.NORTHSTAR.` note holds the multi-year "why" that a `.GOAL.` note is too short-lived to carry — a small number of long-horizon **Waypoints** that projects and areas can declare they serve. Part of the **Steering Pack** module.

## What this template is for

A `.GOAL.` note answers "what matters this quarter?" A North Star note answers a slower question: "in two or three years, what does 'this actually worked' look like, and what are the handful of checkpoints on the way there?" Without this layer, every quarter's GOAL file can look busy and productive while the underlying multi-year direction quietly drifts — nothing in the base system catches that, because a GOAL file only ever looks one quarter deep.

Keep this note nearly static. If you're editing it every month, you're either writing a GOAL note by mistake, or the Waypoints were set wrong to begin with.

## Required frontmatter fields

```yaml
---
Type: "North Star"
Period: "<e.g. 2026-2027>"
Status: "Active"
---
```

## Required sections

1. `## The North Star` — one or two sentences: the multi-year destination, written concretely enough that you'd know if you'd arrived.
2. `## Waypoints` — 2–4 numbered checkpoints (`W1`, `W2`, `W3`, ...) on the way there, each with: a one-sentence definition of "reached," and roughly when you expect to reach it. Waypoints are sequential milestones, not a task list — no checkboxes here.
3. `## Review notes` — dated one-line entries, same discipline as a `.GOAL.` note's review section: what shifted, added once, history never rewritten.

## The `Serves::` field

Any `.PRJ.` or `.AREA.` note can declare which Waypoint it's working toward with a frontmatter field:

```yaml
Serves: "W1"
```

This is what `scripts/serves_mapping_report.py` (Steering Pack module) reads to build a coverage report — which Waypoints have active work pointed at them, and which projects/areas aren't serving any Waypoint at all (not automatically a problem — plenty of maintenance work doesn't need to — but worth seeing at a glance).

## Worked example

`[[2026-2027.NORTHSTAR.grow-brightline-studio-into-a-full-time-business]]`

## Notes on using this template

- **A North Star note lives at the vault root**, dated by the period it covers, the same "cuts across PARA categories" exception as `.GOAL.` notes (see `AI_INSTRUCTIONS.md` § "File naming conventions").
- Most solo operators only need ONE active North Star note at a time. If you're tempted to write a second one for a different part of your life, ask first whether that's really a separate destination or just a different Waypoint on the same one.
- A `.GOAL.` note's work streams are the *how* for one quarter; a Waypoint is the *what, eventually*. Not every GOAL-file task needs to trace to a Waypoint — but if an entire quarter's GOAL file serves no Waypoint at all, that's worth noticing at your next Waypoint review.
